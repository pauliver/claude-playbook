# Hard-won lessons

One line each, each paid for in a real repo. The rules they produced: [`way-of-working.md`](../user-level/way-of-working.md).

Sources: obs = Observatory, the terminal/fleet tool · photo = a photo-library app · game = a game repo · party = a
party game · disk = a disk-space tool · notes = a second-brain/notes repo · engine = the oldest repo, an agent-built
C++ engine · early = the first two months · machine = the machine-level rules · history = the prompt-history analysis.

## Evidence and "done"
1. A green build is not a working feature; verify through the user's path. Build-and-launch is a pre-flight, never the verdict. [all, engine]
2. `ok: true` is not proof the state changed; compare before and after. [photo]
3. Look at a screenshot before citing it (a "filter working" shot showed the unfiltered grid); a mounted widget is not a painted one. [photo]
4. Prove a deploy by a new capability, never a version string; close the issues it proves then. [photo]
5. "Does it exist?" ≠ "does it work?": a registered runtime stub silently ignored every tool for a session. [early]
6. Unknown is not zero: a confident 0 reported 36,274 unanalysed items as done. [photo]
7. Honest absence: no synthetic or demo fallback; fail loudly with what, where, why. [photo, early]
8. A feature that is a predicate over someone else's state stays dead until a caller sets that state. [photo]
9. Wired-but-dead (nothing calls it) and inert lanes (called, but the guard can never be true) both look healthy; ask what values the condition can take. [obs]
10. A config value nothing reads is not a setting — ask the tool what it resolved; `channel = "stable"` is not a pin. [photo]
11. A green gate on a grandfathered setup can't test a change in how trust is established; say whether you verified from cold. [obs]
12. Test claims need same-binary proof: built after the last commit, new tests listed by name from it, zero = void. Three agents reported passes their binaries couldn't produce. [engine]
13. Rebuild from latest before showing the owner, or say "this is the OLD build". [engine]
14. A review that finds missing functionality is a FAIL, not PASS-with-note; check every planned item. [engine]
15. Reproduce on current main before diagnosing (several bug-bash picks were already fixed); check "not on main" with `git show origin/main:<path>`. [engine]

## Tests
16. A test must be able to fail: red-check it by mutation, and prove the mutation applied. [photo, obs, game]
17. A check whose PASS is an absence must prove it looked: an empty `grep Fail` is green on zero tests. Count by name or per lane. [photo, game]
18. Self-certifying tests: an expected value built by the code under test agrees only with itself; faking the message a system listens for certifies the listener, not the producer. [photo, game]
19. A source-scan guard pins a spelling, never a value; pair it with a behavioural test. [obs]
20. "Comment-only ordering constraints" come in two kinds that look identical; only mutation tells them apart. [obs]
21. No test-only branches in production code. [game]
22. State an oracle's power (expected hits, chance of missing); a threshold between two regimes is a coin flip. [game]
23. A new detector's first run is part of building it; try to fool it before trusting it. [game]
24. A skip gate needs a hard-FAIL canary exercising the same setup. [game]
25. Fixtures must be real-shaped and present on every machine; invented fixtures hid three data-losing parser bugs. [early, photo]
26. Assert identity, not arithmetic: a row-count test passed for months while every ID churned. [early]
27. Compare captures against labelled known-BAD baselines as well as good ones. [engine]
28. Split verdicts into product vs infrastructure failures, with distinct exit codes. [engine]
29. Test runs stay out of the live tree (pin cwd in the same command; a stray file made a phantom defect) and revert untasked changes before a bookkeeping commit. [engine]

## Gates and builds
30. One gate, one command, every lane; a subset is not the gate. Documented raw commands once ran 0 of 2,600 tests. [obs, photo]
31. Gate the merged tree, re-verify after every rebase, and don't edit what a running gate builds; two green branches can merge red. [photo, game]
32. Gate the push on the verdict in the same command, keyed to the tree tested: a pipe exits with `tail`'s code, and a bypass flag shipped a red commit. [photo, party, obs, game]
33. Long jobs must outlive the session: nohup plus a sentinel line. [photo]
34. A red gate is a real defect: name the mechanism or say NOT DIAGNOSED, never "flaky". "Passes alone" is weak; re-run under load and count. [photo, obs]
35. Green on one OS is that OS's verdict: a macOS-green epic hit 11 failures on its first Windows run; `rand()` differs across compilers. [obs, engine]
36. Anything that can differ between OSes at build time must fail loudly at build time. [obs]
37. Gates over-flag: a false alarm is tolerable, a false pass is not. Fix the cause of false reds (they rot a gate too), never loosen to silence noise; report every failure. [game, engine]
38. An environment difference that turns the gate red is a gate defect; fix the gate, don't add a reminder. [photo]
39. A suppression or skip-verify needs a reason, an open issue, a log entry and an expiry; expired ones are loudly ignored. [engine]
40. Under `set -e`, `((var++))` aborts when var is 0; use `var=$((var+1))`. It killed 8 runs of a passing validation. [engine]

## Measuring and debugging
41. Measure, don't theorise: every unmeasured cause asserted over two days was wrong. [photo]
42. Measure the thing, not its proxy; name the competing explanation and cross-check against a fact the tool didn't produce. [photo]
43. When two ways of counting disagree, the disagreement IS the finding. [game]
44. A cost guessed from a structure's shape or one shallow sample is a guess; bench the caller. [photo]
45. Progress bars lie; measure the underlying signal over minutes. [early]
46. A run past its budget is a prompt to measure: runaway processes, CPU time, backups, load — then the code. [photo]
47. Rank context costs in tokens per modality; ranking by characters nearly killed the look-at-the-screenshot rule. [game]
48. Baselines are the median of 3+ settled runs, never the best, with load recorded. [photo]
49. Read the frames, many of them; `allocs=N frees=M` with N≠M is a leak even when the line says "no leaks". [engine]
50. A verdict like "BLACK_SCREEN" names a symptom: the ~90 KB PNG wasn't black, a menu was on top. [engine]
51. The four fidelity laws: ground truth first; whole region, not filtered to expectation; ≥3 runs for races; one symptom can have two owners. [engine]
52. Track a revert-to-isolate on the issue; a "verified" fix was reverted and never re-applied. [engine]
53. Same bug back 3+ times → trace the whole pipeline, working vs broken; N bugs, one symptom → suspect one root cause (three "regressions" were one). [engine]
54. Analysis paralysis: 5+ reads with no action → stop and say why; 3 failed attempts → step back. [engine]

## Git and GitHub
55. Stage by name, never `git add -A` on a shared tree; pathspec commits skip untracked files, so `git add` them first. [photo, game, obs]
56. No closing keyword near `#N`, even negated (it closed issues five times), nor in a PR body (closes on merge, before verification). [photo, game, engine]
57. Read `gh issue view N --json title` before acting on a number; task numbers collide with issue numbers. [game, photo]
58. Claim with a comment and `git fetch` before a work block; the same fix was once written twice on two machines. [game]
59. Cite a sha only after the push (rebase rewrites it); read shas from `git log`, never from an agent's prose. [obs, party]
60. Prove the target before mutating a remote: a transfer from the wrong directory renumbered 41 issues, exit 0. [obs]
61. `--theirs` takes the whole file; `pull --rebase` flattens a merge. [photo]
62. Prefer `gh` over raw git https; the keychain helper can hang silently. [obs]
63. Branches are how we lose work: merge lanes the same day, capture the tip sha, delete (62 dead branches → 5). [photo, obs, engine]
64. A worktree can hold the only copy as staged-but-uncommitted changes; check `status --porcelain` before removing it or trusting its label. [obs, notes, engine]
65. `git status` and `git stash list` before any destructive op; never blind-drop another session's stash (one held 400+ never-committed assets). [engine]
66. Prove a branch redundant by reverse-applying its patch (squash merges make log/cherry lie); `git ls-remote --heads origin` is the only truth (17 "open branches" were 3). [engine]
67. Landing is one atomic routine: merge → confirm the issue closed → release the lock; closing before merge nearly lost a fix. [engine]
68. Work from another AI tool is cherry-picked, never branch-merged; treat every file it touched as suspect. [engine]
69. Append-only registries with deterministic ids can merge with `merge=union`, removing a serialisation point. [engine]

## Agents
70. Never self-verify: 33 green tests missed three critical lifecycle bugs. [game]
71. Put "DO NOT PUSH" first in every brief; never phrase a gate as "push on your PASS". [game, party]
72. A background agent's plain final text reaches nobody; make sending the report its LAST action, or run it in the foreground. [obs, game, engine]
73. A dead agent looks like a clean one: reconcile dispatched vs finished by name; judge a silent one by new commits, output mtime and lock, not its transcript. [obs, engine]
74. Stop finished agents at once (19 idle piled up, each wake-up re-reads its transcript); SendMessage revives a stalled one ~50% of the time — relaunch instead. [engine]
75. Worktrees are cut from `origin/HEAD`, not your branch: push first and put a base check in the brief; give each one plain commands and a private scratch dir. [obs, party]
76. State what not to re-derive (agent re-entries were the costliest turns); a second-hand finding is a claim to falsify. [game, photo]
77. Spot-check agents' file:line claims; experts hallucinate line numbers. [game]
78. One verifier with a reproduction outranks eleven without. [obs]
79. A class guard written by the fix's author shares its blind spot; have another agent write it. [obs]
80. Re-derive merge risk from the changed paths; the implementer's self-assessment is input, not the verdict. [engine]
81. Integration is serial, review parallelises (five full suites at once: load 140). Split lanes by file ownership, then one reviewer over the merged range. [obs]
82. Fan-out width = min(RAM, CPU), measured: a session costs ~8 GB, and a small Mac ran out of memory at three. [game, engine]
83. The Producer must be top-level: nesting is one level deep, so a subagent Producer's dispatches silently fail. [engine]
84. Never /loop an orchestrator: 4–5 workers each became 20–25 Claude processes and crashed the machine three times. [engine]
85. Agent types load at session start (fall back to general-purpose + "read the agent file"); read a skill or agent file before dispatching with it. [party, game, early]
86. Every dispatch carries SUCCESS_CRITERIA, echoed verbatim by the worker (none → DECISION_NEEDED); the report states whether they were met, with evidence. [engine]
87. Size tasks to the worker's budget; oversized issues produced nothing. [early]
88. Pre-existing failures on main poison every worker's gate; fix them first. [early]
89. A missing script is a fallback trigger, not a stop: do what it would have done. [engine]
90. A relayed or inferred approval is not an approval. [photo]

## Docs and memory
91. One copy of every fact; a second copy drifts, and a note that a doc is wrong decays like the doc — correct at the claim. [all, photo, obs]
92. Memory is not enforcement: a rule broken twice becomes a check — right-sized (rules demanding four sections per skill hit 97% non-compliance). [photo, game, engine]
93. A memory only one machine can read makes it confident and the rest wrong. [obs, party, disk]
94. Migrate before delete; machine-local stores aren't recoverable (~21 unique items lost). [engine]
95. An index past ~24 KB gets its tail cut from context. [photo]
96. Huge append-only tables become unreadable; split into an index plus a page per item. [game]
97. Measure the bootstrap reading list against transcripts: eight mandatory reads (~62k tokens) were almost never read. [game]
98. Cite symbols, not line numbers. [photo]
99. A doc-freshness pass re-derives status from code; it never re-stamps a banner. [game]
100. A status word must not read as its opposite ("build-ready"). [photo]
101. Never document fiction: mark PLANNED; raise doc/code mismatches, don't silently fix the doc. [engine]

## Shell and machine
102. A timeout bounds your wait, never the syscall; never walk roots that may contain network mounts. [machine, disk]
103. Never kill by process name; attribute by PID and command line. [game, obs, photo]
104. What you leave running stays running: audit by path and port; never retry-loop a failed launch (each pops a dialog). [engine]
105. Wait on a PID or sentinel, never `while pgrep -f` (it matches itself) or a sleep-poll; never restart a long job you can't prove dead. [photo, game]
106. Chain build and test with `&&`, never `;`. [game]
107. The harness can move the cwd between calls; use `git -C <abs>` and check the content landed. [photo]
108. Restoring a file by copy keeps its old mtime, so the build skips it; touch it. [game]
109. A shell function can shadow a system tool (`log` in zsh); use absolute paths. [early, photo]
110. Several unrelated tools failing together is the signature of a toolchain licence or update. [machine]
111. Build servers stay resident unless told not to (87 idle nodes, 9.4 GB); set the env vars in repo settings. [obs]
112. A tool-server timeout inside a GUI app usually means a modal dialog. [game]

## Working with the owner
113. Ask decisions last, one at a time, as buttons, recommendation first. [party, photo, game]
114. Never end a turn on a next step you can take; context limits are not a stop condition. [game, obs, early]
115. When the owner is live and has approved, be decisive; don't defer thinking to a timer. [engine]
116. Triage by how success is checked: machine-verifiable solo, eyes-verifiable batched with the owner; time-box blind visual debugging. [engine]
117. Engineering-green is not "fun" or "balanced"; stop at the plan's end and hand over a play-test list. [game]
118. Don't add risk to working code without a gain the owner would notice. [obs]
119. Never dumb down the product to make it testable; make the harness catch up. [party]
120. Repeated prompts become skills. [history]
